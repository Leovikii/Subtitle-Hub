# 系列用语规范

## 1. 目的与位置

同一系列的不同季度、续作、电影和特别篇必须共用人名、地名、组织、舰船、装备及技术术语。每个系列目录只建立一个活动规范：

```text
works/<series>/
├─ README.md
├─ series-guide.md
└─ <work-id>--<work-slug>/
```

不得在各项目 `docs/` 复制同一术语表，也不得为每一季建立互不关联的 glossary。项目开始前必须读取系列表；新作品发现的新词回写同一个 `series-guide.md`。

## 2. 建立和扩充

首次建立系列时，应检索中文维基百科的系列页、作品页和角色页，必要时补充官方中文发行材料、原文官网及当前仓库已确认译本。维基页面是公开候选来源，不是无条件权威；必须结合日文原词、上下文和现有项目一致性判断。

每个术语必须有稳定 `term_id`，并记录：类别、日文原词、规范简体中文、禁用或待替换形式、适用范围、来源、状态和备注。不得只列中文词而丢失原文锚点。

## 3. 状态和歧义

- `confirmed`：证据一致，可作为系列强制译名；
- `provisional`：当前项目暂用，加入新作品前必须复核；
- `pending-user-confirmation`：存在实质歧义，不得用于批量替换。

当中文维基、既有字幕、官方材料或不同作品之间出现冲突时，agent 必须把候选译名、原词、来源和影响范围提交用户。用户确认后才能把条目标记为 `confirmed` 并继续相关项目。不得以多数出现次数自动决策。

## 4. 使用与覆盖

系列表中的 `confirmed` 项对该系列所有项目生效。项目确因时代、世界线、官方改名或剧情语义需要不同译法时，只能在项目 `docs/project-guide.md` 建立明确 `override`：引用 `term_id`、限定范围、给出作品内证据并记录用户确认。

自动检查可以报告禁用形式和未知变体，但不得对人物名、音译名或语境相关术语直接批量替换。确认修改仍须进入项目修改台账。

## 5. 维护门禁

新季度或新续作进入正文校对前必须完成：

1. 读取现有系列表；
2. 从新作品原语字幕抽取专名候选；
3. 与系列 `confirmed` 项对齐；
4. 检索中文维基及必要的官方来源补充新词；
5. 把冲突项交用户确认；
6. 更新系列表并完成新项目术语差异审计。

未完成以上步骤时，不得宣称新项目已具备统一术语基线。
