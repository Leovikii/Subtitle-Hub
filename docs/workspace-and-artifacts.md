# 项目工程区、临时产物与归档规范

## 1. 原则

- 本仓库统一工作区边界、生命周期和审计要求，不强求不同作品共用同一套处理脚本。
- 不同字幕范本的来源结构、错听类型、样式和分轴问题不同；项目可以编写一次性脚本，但必须限制在当前作品的临时工具目录。
- 原始来源、长期工作主稿、未审临时产物、待发布构建和历史归档必须物理分开。
- 临时脚本、中间产物和开发者审核报告不是长期基准。影响字幕的结论必须回写项目规范、进度、修改台账或问题台账。

## 2. 标准结构

```text
project/
├─ sources/                         # 只读来源
├─ workspace/
│  ├─ episodes/<episode>/master.ass # 长期工作主稿
│  ├─ temp/                         # 可整体清理，不纳入 Git
│  │  ├─ tools/                     # 当前项目的一次性脚本和小工具
│  │  ├─ intermediate/              # 映射、抽取、转换和分段中间文件
│  │  ├─ review/                    # 审查通过前的字幕候选、表格和画面样本
│  │  └─ logs/                      # 调试输出、运行日志和性能记录
│  └─ build/                        # 通过本轮检查的待发布构建，可重新生成
└─ archive/                         # 经清单和校验值冻结的历史工程压缩档案
```

作品正式产物仍位于作品根目录 `subtitles/vX.Y.Z/`，人工可读规范和审计记录仍位于作品根目录 `docs/`。`workspace/episodes/`、`docs/`、`sources/`、`archive/` 和 `subtitles/` 都不属于临时清理范围。

## 3. 各区域的生命周期

### episodes

保存下一版本的唯一工作主稿并纳入 Git。任何脚本都必须读取来源或主稿后写出新文件，再经比较和确认替换主稿；不得让某个临时中间文件成为未声明的真实基线。

### temp

`temp/` 中所有内容默认可删除、不可发布、不可作为唯一证据，也不得由正式字幕或项目文档建立运行时依赖。脚本可以按轮次建立更深的子目录，但必须保持在上述四类之内。

- `tools/`：项目专用脚本、试验命令封装和一次性检查器；
- `intermediate/`：解析结果、语言映射、格式转换、临时拆分与合并文件；
- `review/`：尚未通过人工或项目门禁的候选字幕、候选表、截图和对比结果；
- `logs/`：可重复生成的标准输出、错误日志和运行记录。

开发者审核报告和附件都保留在 `temp/review/`。人工确认后，将规则反馈写入 `docs/project-guide.md`、进度反馈写入 `docs/progress.yaml`、实际修改写入 `docs/change-log.tsv`、未解决问题写入 `docs/issues.tsv`；完成回写后才可清理报告和附件。

### build

`build/` 只接收从当前主稿生成、已完成本轮规定检查的待发布文件。它不是正式版本，也不纳入 Git；发布时复制到新的 `subtitles/vX.Y.Z/`，生成并核对校验值后可以清空。

### archive

`archive/` 用于保存已经停止维护、但因追溯价值不能直接丢弃的旧工程文件。每个压缩档案必须具有：

- 稳定文件名和归档日期；
- 原路径清单、文件大小和逐文件 SHA-256；
- 压缩包 SHA-256；
- 项目 `docs/` 中的归档说明和适用限制。

归档不是普通工作备份，也不是现行 pipeline。需要恢复时应解压到 `workspace/temp/intermediate/`，不得覆盖当前主稿、来源或正式产物。

## 4. 一次性自动化的使用规则

1. 在 `temp/tools/` 创建脚本，在文件头或同轮日志中说明输入、输出和适用范围；
2. 输入只能来自显式路径，来源目录保持只读；
3. 输出先写入 `temp/intermediate/` 或 `temp/review/`，不得直接覆盖主稿；
4. 比较候选与主稿，将确认的实质修改逐项登记后再更新主稿；
5. 将需要长期保留的报告和台账迁入 `docs/`；
6. 本轮结束后清理 `temp/`，需要发布时从已确认主稿重新构建 `build/`。

只有工具已经证明可以跨多个作品复用、输入输出契约稳定，并配有测试和独立说明时，才应另行提议升级为仓库级工具；不得为了形式统一提前建立空泛的通用 pipeline。

## 5. 清理底线

清理前必须解析并确认目标位于当前作品的 `project/workspace/temp/` 或 `project/workspace/build/` 内。禁止用未解析变量、宽泛通配符或作品根目录执行递归删除。以下内容不得随临时区一起删除：

- `workspace/episodes/` 工作主稿；
- `sources/` 原始来源；
- `docs/` 规范、报告和台账；
- `archive/` 历史档案及清单；
- `subtitles/` 正式版本。
