# 作品身份、外部 ID 与成品名称规范

## 1. 建项前置门禁

创建作品目录前，AI agent 必须主动检索 IMDb 和 Bangumi 的作品条目，并把候选与实际作品范围逐项核对。豆瓣因条目覆盖、访问和消歧局限较大，不得作为主动检索门禁；只有用户提供豆瓣 ID 时，才把它作为可选映射记录。检索必须区分：

- TV 季度、OVA、电影、总集篇和剧场先行版；
- 原作、重制版、续作和同名作品；
- 首播年份、集数、媒介类型和原始标题；
- 系列名与本季度完整中文名。

搜索结果页只用于发现候选，能访问详情页时必须回到平台详情页核验。若 IMDb 或 Bangumi 没有对应条目或详情页当前不可访问，必须如实记录 `not-found`、`access-blocked` 或 `user-confirmed`，不得把搜索摘要伪装成平台核验。不得为了补齐豆瓣字段主动检索或猜测豆瓣 ID。

## 2. 必须暂停的歧义

出现以下任一情况时，AI agent 必须暂停建项并向用户同时给出候选 ID、候选中文名和产生歧义的证据：

- 平台条目的年份、集数或媒介类型互相冲突；
- 中文名无法区分季度、电影版或总集篇；
- IMDb 候选不是完整作品条目，而是单集、特别篇或合集；
- 同一平台存在两个同样合理的候选；
- IMDb 条目名称或项目中文标题需要在多个候选间作实质选择。

只有用户确认 ID、IMDb 条目名称和项目中文标题后才能继续创建项目、系列术语表或正式包。确认结果写入 `project.yaml`，不能只留在聊天或临时报告中。

## 3. project.yaml 身份记录

项目唯一元数据文件必须记录：

- 仓库内部 ID、作品类型、集数和多语标题；
- IMDb、Bangumi 各自的 ID、平台标题、详情 URL、核验状态和核验日期；
- 用户提供时才记录豆瓣 ID，并标记为可选、用户确认；
- 项目用于目录和中文展示的中文标题；
- IMDb ID 必须是作品级 `tt` 编号。

核验状态只使用：

- `agent-verified`：agent 已从平台详情页或足以唯一定位的公开页面核对；
- `user-confirmed`：用户明确提供或确认，但 agent 无法独立访问详情页；
- `not-found`：完成合理检索仍未发现条目；
- `access-blocked`：已发现候选，但当前环境无法读取足够证据；
- `pending-user-confirmation`：存在歧义，必须停止建项。

`not-found` 和 `access-blocked` 不是猜测 ID 的许可。豆瓣未提供时使用 `null`，不记为建项缺陷。后续发现新证据时更新同一个 `project.yaml`，不得另建身份说明文件。

## 4. 面向用户的成品包名

ZIP 固定命名为：

```text
<imdb-id> - <IMDb-title> [v<version>].zip
```

例如：

```text
tt2496120 - Space Battleship Yamato 2199 [v1.0.1].zip
```

IMDb ID 位于最前，以 ` - ` 连接 IMDb 条目名称，并在末尾使用 `[v<version>]` 标注版本，避免仓库另行维护一套包名标题。不得加入仓库内部 ID、项目中文标题、豆瓣 ID、Bangumi ID、语言说明或发布组名称。文件名版本用于快速识别，仍须与包内 `VERSION` 一致；语言信息从字幕文件名读取。

IMDb 名称若含 Windows 禁止字符 `<>:"/\\|?*`，打包脚本只把这些字符替换为带空格的 ASCII 连字符 ` - ` 并合并连续空白；除此之外不得改写、翻译或重排 IMDb 名称。IMDb ID、名称或当前版本改变时，自动打包必须删除旧的生成包，只保留新名称。
